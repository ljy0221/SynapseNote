항목 | 규칙

클래스명 | PascalCase
변수명 및 메서드명 | camelCase
상수명 | UPPER_SNAKE_CASE
패키지명 | lowercase
탭 사용 | 공백 4개

제어문 블록 {} | 같은 줄 시작

### 2. 커밋 메시지 컨벤션

**커밋 메시지는 type: message 형식을 따르며, 아래의 규칙을 따릅니다.**

**제목 규칙**

- 제목은 lower-case로 작성합니다.
- 제목 끝에 마침표(.)를 사용하지 않습니다.
- 제목은 최소 5자 이상이어야 합니다.
- 전체 헤더는 72자를 초과하지 않아야 합니다.

타입 | 설명
-- | --
build | 빌드 시스템 또는 외부 종속성 관련 수정
chore | 자잘한 작업, 코드 수정 외 기타 작업
content | 컨텐츠(게시글, 데이터) 관련 수정
docs | 문서(README, Wiki 등) 수정
feat | 새로운 기능 추가
fix | 버그 수정
refactor | 코드 리팩토링 (기능 추가나 수정 없이 구조 개선)
style | 코드 포맷팅, 세미콜론 추가 등 코드 변경이 없는 스타일 변경
test | 테스트 코드 추가 또는 수정
deploy | 배포 관련 설정 변경 및 배포 작업
setting | 코드 외 환경 설정 관련 작업
hotfix | main 브랜치에 수정해야할 작업

#### 커밋 메시지 형식
<pre><code>type: 제목

본문 (선택 사항)

</code></pre>

예시
<pre><code>feat: 기능 요약

기능에 대한 간단한 설명 추가

</code></pre>

### 3. 추가 규칙
<ul>
<li>PR 제목은 커밋 메시지와 동일한 형식을 유지합니다.</li>
<li>main 브랜치는 코드 리뷰를 거친 후 병합을 수행합니다.</li>
</ul>
